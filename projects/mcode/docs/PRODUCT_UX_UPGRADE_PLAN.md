# Mcode App 产品级体验提升方案

## 1. 背景

Mcode App 已经具备 agent 主循环、工具调用、项目/会话管理、事件流、文件树、终端、subagent、todo、git/checkpoint、上下文压缩等底层能力。

当前主要问题已经不再是“能不能跑”，而是“能不能让普通用户稳定、清楚、放心地使用”。现阶段 UI 和输出体验仍偏工程实验原型：

- 主对话区容易暴露内部事件，用户阅读负担重。
- LLM 最终回答容易变成报告式模板，标题、emoji 和完整回顾过多。
- 工具执行过程、命令输出、最终回答、文件改动之间的信息层级不够清晰。
- 文件改动虽然已有 checkpoint 和初版审核卡，但 diff、撤销粒度、命令产生的文件变更仍不够产品化。
- 任务完成状态、审批状态、失败重试、撤销确认等用户决策路径还不够统一。

本方案目标是把 Mcode App 从“可验证原型”提升为“Codex 风格本地 agent 控制台”的产品级第一阶段。

## 2. 产品目标

### 2.1 核心体验目标

用户提出任务后，主界面应该稳定呈现为：

```text
用户消息
-> 可折叠的思考与工具过程
-> 简洁的最终回答
-> 文件改动审核卡
-> 用户确认 / 撤销 / 继续提问
```

右侧面板承担完整工程信息：

```text
文件树 / 文件预览 / 终端 / 后台任务 / 事件流 / subagent 状态
```

### 2.2 产品原则

- 主对话区面向用户决策，不作为原始日志面板。
- 右侧面板保留完整信息，支持调试和追溯。
- 最终回答要像工程交接，而不是报告生成。
- 任何文件改动都应尽量可审查、可撤销、可确认。
- 任务状态必须明确，不能让用户猜 agent 是否还在运行。
- 失败要可理解、可恢复、可重试。

## 3. 非目标

本阶段不做以下内容：

- 不做插件市场。
- 不做完整 macOS 原生打包体验优化。
- 不做多人协作。
- 不做云端同步。
- 不做复杂 IDE 编辑器。
- 不做完整 git GUI。
- 不追求 SWE-bench 级自动评分集成。

## 4. 改动范围

### 4.1 最终回答风格治理

#### 问题

当前模型输出可能出现：

```markdown
### 📋 完整工作回顾
**1. 创建仿真脚本**
...
```

这种风格信息密度低、视觉噪声强，不适合 agent 产品的日常使用。

#### 产品改动

1. 强化 system prompt
   - 禁止装饰性 emoji。
   - 禁止“完整工作回顾”式模板。
   - 禁止重复工具调用过程。
   - 最终回答优先包含：结果、关键文件、验证、下一步。
   - 默认控制在 3-8 行。

2. 新增 `FinalAnswerRenderer`
   - 对最终回答做前端展示优化。
   - 自动识别文件路径、命令、测试结果。
   - 长回答默认折叠。
   - 支持“展开完整回答”。

3. 建立回答风格测试集
   - 用固定任务检测是否出现报告腔、emoji、过度标题。

#### 验收标准

- LFM 仿真任务最终回答不出现 `📋`、`完整工作回顾`、`**1. 创建...**` 这类模板。
- 最终回答第一段必须直接说明结果。
- 如果产生文件，回答必须包含关键文件路径。
- 如果运行了脚本或测试，回答必须包含简短验证结果。
- 默认回答在主对话第一屏内可读完。
- 长回答折叠后不影响输入框和滚动。

## 5. 主对话区信息分层

### 5.1 问题

主对话区曾混入：

- `compact_check`
- `compact_skipped`
- `checkpoint_saved`
- `command_output`
- `turn_completed`
- `controller_started`

这些是系统内部事件，不应该直接展示给普通用户。

### 5.2 产品改动

1. 事件可见性分级

```ts
type EventVisibility = "chat" | "timeline" | "debug" | "hidden";
```

2. 主对话只显示：
   - 用户消息
   - assistant 最终回答
   - 思考与工具过程组
   - 改动审核卡
   - 审批提示
   - 关键错误

3. 思考过程组
   - 运行中默认展开。
   - 成功后默认折叠。
   - 失败或等待审批时保持展开。
   - 内部只显示工具摘要，不显示长日志。

4. 时间顺序修复

正确顺序必须是：

```text
用户消息
思考过程
assistant 最终回答
改动审核卡
```

### 5.3 验收标准

- 主对话区不显示内部事件名。
- 一轮任务结束后，思考过程自动折叠。
- 正在运行的任务，思考过程默认展开。
- 错误任务，思考过程默认展开并突出错误工具。
- `command_output` 不进入主对话区。
- unknown event 不导致 UI 崩溃。
- 右侧 Events 面板仍可查看完整事件流。

## 6. 工具卡与命令输出体验

### 6.1 问题

命令、Python 脚本、bash 输出如果直接刷在主对话，会破坏阅读体验。

### 6.2 产品改动

1. 工具卡统一结构

```text
工具名 | 摘要 | 状态 | 用时 | 展开按钮
```

2. Python 工具卡显示：
   - Python 解释器路径。
   - Conda 环境名称。
   - 运行文件。
   - 退出码。
   - 输出摘要。

3. Bash 工具卡显示：
   - 命令摘要。
   - 审批状态。
   - 退出码。
   - 输出摘要。

4. 长输出处理
   - 主对话只显示最后 20-40 行摘要。
   - 完整输出进入右侧 Terminal / Jobs。
   - 支持展开完整输出。

5. GUI 弹窗防护
   - Python 执行默认设置 `MPLBACKEND=Agg`。
   - 图像输出必须保存到文件。

### 6.3 验收标准

- 运行 Matplotlib 脚本不会弹出 GUI 图窗。
- 主对话不会被 stdout/stderr 刷屏。
- 工具卡能显示 running / done / error / blocked。
- 命令失败时显示退出码和关键错误。
- 右侧 Terminal/Jobs 可查看完整日志。
- Python 工具卡能显示当前解释器或环境信息。

## 7. 文件改动审核卡

### 7.1 当前状态

已有第一版改动审核卡：

- 显示 `已编辑 N 个文件`
- 显示新增/删除行数
- 显示文件列表
- 支持确认
- 支持按本轮 checkpoint 撤销

### 7.2 产品改动

1. 增强审核卡展示
   - 显示文件列表。
   - 显示每个文件新增/删除行数。
   - 支持展开 diff。
   - 支持复制 diff。

2. 撤销能力分层
   - 撤销全部。
   - 撤销单个文件。
   - 确认全部。
   - 已确认后不能重复确认。
   - 已撤销后不能重复撤销。

3. 改动来源识别
   - `write_file`
   - `edit_file`
   - `python_run`
   - `bash`
   - git 操作

4. 命令产生的文件变更
   - 对 `python_run` / `bash` 前后做 workspace 快照。
   - 检测新增、修改、删除文件。
   - 如果无法精确 checkpoint，明确提示“由命令产生，无法逐行恢复”。

5. 风险提示
   - 修改用户已有未提交改动。
   - 删除文件。
   - 覆盖已有文件。
   - 修改 workspace 外文件。
   - 生成大文件。

### 7.3 验收标准

- `write_file` 创建文件后，审核卡显示正确文件数和新增行数。
- 点击撤销后，新建文件被删除。
- `edit_file` 修改文件后，撤销能恢复旧内容。
- 确认后状态显示“已确认”。
- 撤销后状态显示“已撤销”。
- 已确认/已撤销后按钮不可重复触发。
- 展开 diff 不破坏布局。
- 文件路径过长时不溢出。
- Python/Bash 产生文件后，审核卡至少能提示新增/修改文件。
- workspace 外文件改动必须触发 ask 或风险提示。

## 8. 审批与安全体验

### 8.1 问题

安全策略存在，但 UI 层需要更明确地表达“为什么需要用户确认”。

### 8.2 产品改动

1. 审批卡显示：
   - 工具名。
   - 操作摘要。
   - 风险原因。
   - 参数预览。
   - 允许 / 拒绝。

2. bash 审批优化
   - 低风险命令可以 allow。
   - 高风险命令 deny。
   - 中风险命令 ask。
   - 审批中输入框状态显示“等待审批”。

3. 审批结果进入事件流
   - `safety_ask`
   - `safety_approved`
   - `safety_deny`

### 8.3 验收标准

- bash 需要审批时，主界面有明显审批入口。
- 用户允许后，agent 能继续执行。
- 用户拒绝后，agent 能收到 blocked 结果并给出解释。
- 审批卡不会被普通消息挤到不可见位置。
- 连续审批不会串 session。

## 9. 任务状态与输入框状态

### 9.1 产品改动

统一任务状态：

```text
idle
creating_session
sending
running
waiting_approval
cancelling
completed
failed
confirmed
reverted
```

输入框规则：

- `idle`: 可发送。
- `sending`: 禁止重复发送。
- `running`: 按钮变 Stop。
- `waiting_approval`: 显示审批提示。
- `cancelling`: 显示取消中。
- `failed`: 显示错误和重试。
- `completed`: 恢复发送。

### 9.2 验收标准

- 发送后不会永久停留在“发送中”。
- turn 完成后输入框恢复可用。
- 运行中重复点击发送不会产生双 turn。
- Stop 能触发 cancel。
- cancel 后 UI 状态回落。
- failed pending message 可重试。

## 10. 右侧面板产品化

### 10.1 文件面板

改动：

- 文件树稳定刷新。
- 点击文件只读预览。
- 改动后自动刷新相关文件。
- diff 卡点击文件可联动右侧文件预览。

验收：

- 切换项目后文件树不串数据。
- 空目录项目正常显示。
- 文件读取越界被拒绝。

### 10.2 终端面板

改动：

- 支持新建终端。
- 支持多终端 tab。
- 显示 shell、cwd、Conda 环境。
- 支持发送命令。
- 支持关闭终端。

验收：

- 新建终端 cwd 为当前项目根目录。
- 输入 `pwd` 显示当前项目路径。
- 关闭终端后状态正确更新。
- 切换项目后不误用旧项目终端。

### 10.3 Events 面板

改动：

- 默认显示关键事件。
- 支持显示 debug 事件。
- 支持按 event kind 过滤。
- 支持复制事件 JSON。

验收：

- 主对话隐藏的内部事件可在 Events 中找到。
- debug 开关开启后能看到 `command_output`。
- unknown event 正常展示。

## 11. Benchmark 验收任务集

建立产品级回归任务，不只测 agent 能力，也测 UI 稳定性。

### 11.1 基础任务

1. 普通对话
   - 输入：`你是什么模型，只用一句话回答。`
   - 验收：最终回答简短，无工具调用。

2. 读文件
   - 输入：`读取 README.md 并总结 3 点。`
   - 验收：出现 `read_file` 工具卡，最终回答不超过 8 行。

3. 写文件
   - 输入：`创建 hello.py，打印 hello mcode。`
   - 验收：出现改动审核卡，可撤销。

4. 修改文件
   - 输入：`把 hello.py 的输出改成 hello codex style。`
   - 验收：出现 diff，撤销后恢复旧内容。

### 11.2 科学计算任务

5. LFM 匹配滤波仿真
   - 输入：`仿真一个 LFM 匹配滤波过程，保存图像并返回关键指标。参数你来设置。`
   - 验收：
     - 生成 `.py` 文件。
     - 生成 `.png` 图像。
     - 不弹 GUI。
     - 最终回答包含关键指标。
     - 主对话不刷屏。

6. 波束形成仿真
   - 输入：`写一个 ULA 波束形成仿真，保存方向图。参数你来设置。`
   - 验收：
     - 生成脚本和图像。
     - Python 运行成功。
     - 输出路径可见。

### 11.3 工程任务

7. Bug 修复
   - 输入：给定一个有 bug 的 Python 文件，要求运行、定位、修复。
   - 验收：
     - agent 能运行脚本复现错误。
     - 修改文件。
     - 再次运行验证通过。
     - 改动卡显示修改文件。

8. 权限审批
   - 输入：要求执行一个需要 ask 的 bash 命令。
   - 验收：
     - UI 显示审批卡。
     - 允许后继续。
     - 拒绝后最终回答说明被拒绝。

## 13. 里程碑

### Milestone 1：主对话产品化

交付：

- Final answer 风格治理。
- 思考过程折叠。
- 主对话事件过滤。
- 改动审核卡第一版稳定。

验收：

- 普通对话、读文件、写文件、LFM 仿真四个任务通过。

### Milestone 2：改动审核增强

交付：

- diff 展开。
- 单文件撤销。
- 命令产生文件检测。
- 风险提示。

验收：

- write/edit/python/bash 文件变更均能被审核卡体现。

### Milestone 3：终端和执行体验增强

交付：

- 工具卡统一。
- Python 环境显示。
- 长输出折叠。
- Jobs/Terminal 联动。

验收：

- LFM、波束形成、bug 修复任务均不刷屏、不弹窗、可查看完整日志。

### Milestone 4：产品级回归套件

交付：

- 8 个 benchmark 任务。
- 前端组件测试。
- 后端 checkpoint/change review 测试。
- 手动验收清单。

验收：

- 每次发布前能完成一轮稳定回归。

## 14. 发布准入标准

进入“产品可用 V1”前必须满足：

- 主对话不显示内部事件。
- 最终回答符合 Codex-like 简洁风格。
- write/edit 文件改动可审查、可撤销、可确认。
- Python 绘图任务不弹 GUI。
- 命令长输出不刷屏。
- 右侧终端可新建、输入、关闭。
- 空项目和真实项目均可正常使用。
- 连续 8 个 benchmark 任务 UI 不崩溃。
- 前端测试通过。
- 后端测试通过。
- build 通过。

## 15. 推荐下一步执行

优先级顺序：

1. 实现 `FinalAnswerRenderer`。
2. 增强改动审核卡 diff 展开。
3. 增加命令产生文件的变更检测。
4. 建立 8 个 benchmark 的自动/半自动执行入口。
5. 对工具卡、终端、事件面板做统一视觉整理。

最先做 `FinalAnswerRenderer + 改动审核卡 diff 展开`，因为这两项能最快改善用户的第一感受，也最接近 Codex 的核心体验。
